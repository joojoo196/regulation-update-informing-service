# 법령 제·개정사항 메일링 웹 서비스 기획

## 1. 프로젝트 개요

국가법령정보 공동활용 Open API에서 환경 관련 법령·행정규칙의 제·개정 및 입법예고·고시 정보를 수집하고, 사용자가 등록한 수신자에게 이메일로 발송하는 웹 서비스다.

Open API 안내: <https://open.law.go.kr/LSO/openApi/guideList.do>

> API 인증키는 문서나 소스코드에 직접 저장하지 않는다. 신청 시 사용한 OC 값은 `LAW_API_OC` 환경변수로 관리하고, 실제 값은 `.env` 및 저장소에 커밋하지 않는다.

## 2. 목표와 범위

### 목표

- 환경 분야의 법령·고시 변경사항을 한 화면에서 확인한다.
- 선택한 수신자에게 변경사항을 이메일로 발송한다.
- 동일 항목의 중복 수집·중복 발송을 방지한다.

### MVP 범위

- 법령정보 API 연동
- 변경·고시 목록 조회 및 분류 표시
- 수신자 이메일 입력·관리
- 사용자의 클릭에 의한 메일 발송
- 발송 성공·실패 결과 표시

### 후속 범위

- 매일 자동 수집 및 예약 발송
- 분야·기관·키워드별 구독 설정
- 회원별 수신 목록과 발송 이력
- 개정 전·후 조문 비교와 상세 링크

## 3. 화면 구성

좌측 사이드바에 다음 두 탭을 둔다.

### 탭 1: 메일 발송

- 수신자 이메일 주소 입력란
- 여러 주소 입력 지원(주소별 추가/삭제)
- 발송 대상 기간 또는 목록 선택
- `메일 발송` 버튼
- 발송 전 확인 창: 수신자 수, 대상 건수, 제목
- 결과 표시: 성공 수, 실패 주소와 실패 사유

기본 메일 제목 예시: `[환경법규 알림] YYYY년 MM월 DD일 법령 제·개정사항`

### 탭 2: 변경 및 고시 목록

필터: 기간, 유형, 법령/행정규칙, 키워드(기본값: 환경 관련).

목록 표현:

#### 변경 법령

- 입법예고
  - XX법
- 개정
  - XX법

#### 최근 변경 행정규칙 목록

- 입법예고
  - XX고시
- 개정
  - XX고시

각 항목은 명칭, 유형, 소관기관, 공포일/시행일 또는 예고기간, 요약, 원문 링크를 표시한다. 항목 클릭 시 상세 화면 또는 원문 페이지로 이동한다.

## 4. 데이터 수집 및 분류

국가법령정보 API 가이드에서 제공하는 법령 변경이력·목록·본문 및 행정규칙 목록·본문 API를 우선 검토한다. 실제 엔드포인트, 요청변수, 응답 XML/JSON 필드는 신청 승인 후 가이드의 해당 API 상세에서 확정한다.

수집 흐름:

1. 기준일(마지막 성공 수집 시각)을 저장한다.
2. 법령·행정규칙 변경 목록을 API로 요청한다.
3. 환경 관련 키워드/소관기관 필터를 적용한다.
4. `source_type`, `item_id`, `change_type`, `published_at` 조합으로 중복을 제거한다.
5. 원문과 메타데이터를 저장하고 화면에 제공한다.

`change_type`은 최소 `입법예고`, `개정`으로 통일한다. 원 API의 분류값이 다르면 변환 규칙을 별도로 둔다.

## 5. 권장 시스템 구조

- 프론트엔드: 사이드바·목록·메일 발송 화면
- 백엔드: API 호출, 필터링, 중복 제거, 메일 발송
- 데이터베이스: 변경 항목, 수신자, 발송 이력, 수집 이력
- 메일 제공자: SMTP 또는 트랜잭션 메일 API
- 스케줄러(후속): 일일 수집 및 예약 발송

API 인증키는 브라우저에 노출하지 않고 백엔드에서만 사용한다.

## 6. 핵심 데이터 모델

- `legal_changes`: id, source_type, source_id, title, change_type, agency, notice_date, effective_date, summary, source_url, raw_payload, created_at
- `recipients`: id, email, is_active, created_at
- `mail_deliveries`: id, recipient_id, change_batch_id, status, provider_message_id, error_message, sent_at
- `sync_runs`: id, started_at, completed_at, status, fetched_count, new_count, error_message

## 7. 비기능 요구사항

- 잘못된 이메일 형식은 발송 전에 검증한다.
- API 타임아웃·호출 제한·일시 장애에 대비해 재시도와 로그를 둔다.
- 메일 발송은 중복 방지 키를 사용한다.
- 인증키·메일 비밀번호·수신자 정보는 로그에 평문으로 남기지 않는다.
- 개인정보 최소 수집 및 수신 거부/삭제 기능을 제공한다.
- 모바일·데스크톱에서 목록과 사이드바가 사용 가능해야 한다.

## 8. 완료 기준

- 승인된 API 인증으로 최근 변경 법령과 행정규칙을 조회한다.
- 입법예고/개정 분류가 화면 요구사항대로 표시된다.
- 유효한 이메일 하나 이상을 선택해 메일을 발송할 수 있다.
- 발송 결과와 실패 사유를 확인할 수 있다.
- 동일 API 데이터를 재수집해도 중복 목록·중복 메일이 생기지 않는다.
- 인증키가 클라이언트 코드와 Git 저장소에 노출되지 않는다.

## 9. 구현 전 확인사항

- 법령정보 공동활용 신청 승인 여부와 API 사용량 제한
- 환경 관련 필터 기준(키워드, 소관기관, 법령군)
- 메일 발송 서비스 및 발신자 주소
- 자동 발송 주기와 발송 시간
- 법적 보관기간 및 수신자 삭제 정책
